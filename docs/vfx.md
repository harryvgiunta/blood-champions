# Ability art, painted textures and proc consequences

Three pipelines, one look. Every key on the bar has a **glyph** on the tile and
a **signature** in the world; every upgrade's trigger draws a **consequence**
where it lands; and both the glyphs and the effects are painted from generated
textures rather than drawn from primitives. This file records the pipelines, the
contracts between them, and how each is verified.

Nothing here is downloaded art. Every pixel is generated by a script in `tools/`
with seeded noise, one fixed light and a fixed palette, so the same command
produces the same files on every machine.

## 1. The icons

`tools/icon_forge.py` is the only source of `assets/ui/abilities/*.png`.

```
python tools/icon_forge.py                  # all 38 icons at 256 px
python tools/icon_forge.py --only fireball,dash --master
python tools/icon_forge.py --sheet --preview 26
```

Each icon is rendered, not drawn: a **signed distance field** per shape is shaded
into a lit piece of a material. That is what separates this set from the first
flat one.

- **Form.** Every shape's distance field is turned into a height profile - a
  beveled edge rising into a lens-shaped body - and the normal of that profile is
  lit. A blade therefore has a bevelled spine, a bright edge and a dark fuller
  because the light says so, not because three polygons were stacked.
- **One light.** A warm key from the upper left and a cool fill from the lower
  right, with a Fresnel rim on every piece. Warm-over-cool is what lets a steel
  edge, a gold guard and a leather grip read as three substances in one picture.
- **Materials are data.** `MATERIALS` holds core/body/edge albedo, roughness,
  metalness, grain direction, specular and rim strength, emissive and ink. A new
  material is one dictionary entry.
- **A shared ground.** Every icon sits on the same lacquer disc with a
  family-coloured rim and a low family glow: one set rather than 38 drawings.
  The disc is inset so the hotbar's own frame still shows around it.
- **Boldness is a size decision.** Every mark is at least ~3.5% of the canvas
  wide, because the hotbar shows icons at 26 px. Details that only exist at
  256 px are kept for the 96 px card; nothing load-bearing is thin.
- **The set is the catalog.** 36 combat skills plus the bandage and the healing
  potion: 38 icons, one file per ability, no file used twice.

`AbilityRules.icon_texture(id)` answers `null` for a row with no file and
`ability_slot.gd` then draws the skill's acronym; that fallback is for a peeled
replica, never a shipped state. `tests/ability_fx_regression.gd` fails on a
missing, unloadable, wrongly sized or *shared* icon.

Godot must import the PNGs (`.import` beside each file, plus a `.uid` for every
new script). Adding art outside the editor needs one import pass -
`.runtime/godot/Godot_v4.7.2-stable_win64_console.exe --headless --editor --quit --path .`
- before `AbilityRules.icon_texture` answers a texture.

## 2. The painted effects textures

`tools/fx_textures.py` writes `assets/vfx/` and its manifest.

| File | Size | What it is |
| --- | --- | --- |
| `flame_8x1.png` | 1024x128 | 8-frame fire plume, white-hot base |
| `smoke_8x1.png` | 1024x128 | 8-frame rolling smoke |
| `spark_4x4.png` | 256x256 | 16 tiles: ember, glint, ash flake, chip |
| `crescent.png` | 512x256 | tapered blade crescent with a hot core |
| `glint.png` | 512x256 | upright swing streak |
| `shock_ring.png` | 512x512 | force ring with a wobbled rim |
| `rune_ring.png` | 512x512 | ward circle with painted runes |
| `splat.png` | 256x256 | blood splat with satellite drops |

`scripts/vfx_library.gd` is the only loader: cached textures, flipbook
particles, atlas particles and one-quad decals, all null-safe (a build without
the sheets falls back to a dot rather than erroring, which is why the regression
asserts the sheets exist, their sizes, and that the flipbooks are actually
wired).

- **Flipbooks** animate through `StandardMaterial3D.particles_anim_h_frames` and
  the emitter's `anim_speed_*`, so one sheet serves every size of flame.
- **Atlas particles** set `particles_anim_*` to 4x4 with a random
  `anim_offset`, so a single burst carries embers, glints, ash and chips at once.
- **Smoke mixes; fire and sparks add.** Smoke that added light would look like
  fog lit from inside.
- The imports keep **mipmaps on** and `detect_3d/compress_to=0`: a flipbook
  quad is seen at every distance, and block compression eats the soft edges.

## 3. Ability signatures

`scripts/ability_signatures.gd` owns the world art of every cue.

- **Entry points.** `cue(parent, rig, definition, cue_name, index, forward, aim)`
  draws one beat and answers whether that id is dressed; `consume(parent, rig,
  kind)` draws the two consumables' completion. `missing_signatures()` names any
  catalog skill without a signature.
- **One writer per beat.** `WarbandAbilities._on_cue` calls the signature *before*
  it spends the hit, on the line the scene already solved, so the light and the
  damage agree. The old generic crescent/impact/spin block in the damage path is
  gone.
- **Two crescents per blade skill, on purpose.** `AbilityFx.slash_arc` lays its
  ribbon flat, which reads from above and is nearly edge-on from the shoulder
  camera; every blade skill therefore also draws the painted upright glint. The
  flat arc says how far the cut reaches, the upright streak says a blade went
  through the air.
- **Rings lie down, walls stand up.** `TorusMesh` is generated around its own Y
  axis, so a ground ring is a torus with *no* rotation; rotating it stands the
  hoop on edge. A crescent wall of force is the opposite: its ribbon is turned
  into the vertical plane. Both were drawn wrong once, and the lookbook is what
  caught it.
- **Rules every helper obeys.** World-space placement, one tween writer per
  property, every node freed on its own clock, no gameplay state read or written,
  no assumption about the rig's API.

## 4. Proc consequences

`scripts/roguelite/proc_fx.gd` (one-shots) and `proc_aura.gd` (a standing field
that pulses and frees itself) own the art of the upgrade engine's decisions.

| Effect kind | Art | Notes |
| --- | --- | --- |
| `arc` | `arc_blade` | thrown shard, afterimage trail, thrower flare |
| `nova` | `nova_ring` | painted ring, flat fan of splinters |
| `chain` | `chain_web` | one jagged web, halo per node |
| `bomb` | `bomb_charge` | planted charge, accelerating pulse, detonation |
| `blast` | `blast_front` | pressure front, dome and radial spikes |
| `splash` | `splash_gout` | droplet arcs and a splat mark |
| `spike` | `spike_ring` | thorns rising in a ring, staggered |
| `whirlwind` | `whirl_vortex` | counter-rotating spiral sheets |
| `shockwave` | `shockwave_arc` | painted crescent wall down the swing line |
| `zone` | `zone_field` | `proc_aura.gd`, for exactly the field's duration |
| `heal` | `heal_motes` | motes rising into the body |
| `currency` | `gold_glints` | spinning coin chips under gravity |
| `bleed` | `bleed_drip` | growing splat and a drip emitter for the dose's clock |
| `wound` | `wound_sear` | two-pulse sear plus embers |
| `double` | `double_flash` | the second booking's staggered flash |
| crit burst | `crit_star` | six-point star, then the front |
| `level_up` | `level_pillar` | light column and rising glyphs |
| elite/boss death | `kill_pop` | ring, ash and a dark flush, sized to the pool |

**Colour names the row.** `ProcEngine` tags a request with `mod` - the catalog
row that fired it - whenever exactly one row owns that trigger. `RunDirector._proc_colour`
mixes the kind's base hue with `Mods.RARITY_COLOUR` for that row, so two players
with different upgrades see different colours from the same hit.

**Host and guest draw the same thing.** The host executes an effect and
broadcasts `{"t": "fx", "kind", "at", "points", "mod", "radius", "seconds",
"power"}`; a guest runs the same function with the same numbers and never applies
damage. Floor art (pools, thorn rings, vortexes, fields) is snapped to the island
floor on both sides.

## 5. Verifying it

| Gate | Command |
| --- | --- |
| Icons (38, unique, 256 px), texture set, flipbook wiring, and that every one-shot frees itself | `Godot --headless --path . --script res://tests/ability_fx_regression.gd` |
| The bar, the ledger and the consumables | `hotbar_regression`, `ability_upgrades_regression` |
| The arena's procs, host and guest paths | `roguelite_regression`, `warband_abilities_regression` |
| Icons by eye, at 256 and at 26 | `python tools/icon_forge.py --sheet --preview 26` |
| Textures by eye | `python tools/fx_textures.py --sheet` |
| Effects by eye | `tools/ui_theme/capture_fx.gd` renders one frame per effect from a fixed camera; `tools/ui_theme/capture_hud.gd` captures the live HUD |

The regression is the contract; the captures are art direction. A green sheet
does not make a skill readable, which is why both capture scripts live in the
repository rather than in a scratch folder.
